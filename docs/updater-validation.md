# Tessera 자동 업데이트 검증 — alpha.4

한국어 | [English](updater-validation.en.md)

기록일: 2026-09-20. 대상은 `0.1.0-alpha.4` / 빌드 `4`, Sparkle `2.10.0`입니다.
자동 검사, 오프스크린 렌더, 실제 로컬 업데이트 흐름을 아래처럼 구분합니다. 이 기록 시점에는
공개 릴리스·Pages·최종 설치본 검증과 Seal 완료가 남아 있으며, 전체 v0.1 완료를 뜻하지 않습니다.

## 자동 검사와 렌더

- 렌더 검사를 켠 Swift 테스트 **170개**가 통과했습니다. 이 중 렌더 검사는 3개이며,
  버전 메타데이터, 업데이트 상태·중복 확인·재시작 설정, 조용한 자동 확인,
  설정/업데이트 창의 앱 표시 수명과 기존 창 배치 회귀 검사를 포함합니다.
- 공개키 기반 서명 검증기의 **13개 회귀 사례**가 통과했습니다. 정상 목록·DMG와 목록만 검증하는 경로,
  서명 블록 뒤 데이터·목록/DMG 변조·다른 키·로컬 URL·릴리스 주소 불일치·현재 빌드 누락·길이 불일치·
  알파 채널 누락·불완전한 표시 버전·중복 빌드 항목의 거부를 확인했습니다. 시험 키는 배포 키와 별개입니다.
- 한국어/영어 × 라이트/다크에서 업데이트 있음·확인 중·최신·오프라인 상태를 렌더했습니다.
  긴 버전 `0.1.0-alpha.100`, 기본 680×800pt, 최소 640×620pt, 스크롤 전체 640×1680pt를 포함합니다.
  오프스크린 렌더는 실제 키 입력·클릭·포커스 이동·VoiceOver 검증을 대신하지 않습니다.

## 실제 Sparkle 로컬 업데이트

alpha.4 후보 DMG를 수정하지 않고, 빌드 번호를 `3`으로 낮춘 별도 시험 앱에서
loopback 피드를 통해 검증했습니다. 시험 앱의 Sparkle 설정은 고유한 `SUDefaultsDomain`으로
격리했습니다. 일반 Tessera 설정은 별도로 보존·비교했습니다.

| 시나리오 | 관찰 결과 |
| --- | --- |
| 잘못된 서명 없는 피드 | Sparkle이 오류 대화상자로 거부했으며 설치로 진행하지 않음 |
| 변조된 DMG | 다운로드 후 설치 전에 서명 검증으로 거부함 |
| 취소·창 닫기 | 시험 앱이 빌드 3으로 남고 실행 파일 해시가 유지됨 |
| 정상 업데이트 | 후보 DMG 다운로드와 Install & Restart를 통해 alpha.4로 교체·재실행됨 |
| 재실행 번들 설정 | 공개 `SUFeedURL`로 복원되고 시험용 `SUDefaultsDomain`이 없음 |
| 프레임워크 로딩 | `vmmap`에서 실행 앱 번들 내부의 Sparkle 로딩 경로를 확인함 |

첫 시험 후 Sparkle 라이선스 리소스를 포함하도록 패키징을 보완했습니다. 런타임 소스는 바꾸지 않았습니다.
이 최종 DMG로 정상 업데이트·재실행을 다시 수행했고, 실행 파일 SHA-256이 최종 `dist/Tessera.app`과
일치했습니다. 최종 appcast와 DMG의 서명 검증도 통과했습니다.

| 최종 산출물 | SHA-256 |
| --- | --- |
| 앱 실행 파일 | `3499da2c3f96e3159cb6ae40d44f5e267a8164add0235e42550d1cdf049125c7` |
| `Tessera-0.1.0-alpha.4-arm64.dmg` | `02b798a657f5b52e3a12ab6501a5a6144350eb12c7ed04adf005a5e61ba1f5ee` |

이 시험 중 원래 `/Applications/Tessera.app`의 alpha.3은 교체하지 않았습니다. 기존 실행 파일
SHA-256 `dce6b39f41b283f4696beedb76f1719907f71bf487740a87f987141bf9e1db67`을 유지했습니다.
시험 사본의 설치 성공을 최종 `/Applications` 설치·접근성 승인이나 다른 Mac의 설치 성공으로 확대하지 않습니다.

## 자동 확인·안내·설정 보존

- 격리한 Sparkle 설정에서 자동 확인을 켠 뒤 실제 예약 확인을 관찰했습니다.
  로컬 서버는 `appcast.xml` 요청만 받았고 DMG 다운로드 요청은 없었습니다.
- 설정 창은 같은 창과 포커스를 유지하며 새 버전 표시를 보여줬습니다. 자동 확인 자체는
  Sparkle 안내 창을 열거나 사용자 작업의 포커스를 가져오지 않았습니다.
- 새 버전 표시를 직접 누르면 한국어 Sparkle 기본 대화상자가 열렸고, Later로 확인 주기를 종료했습니다.
  이는 현재 Mac의 한국어 대화상자 확인이며 모든 macOS 선호 언어 조합의 실기 검증은 아닙니다.
- 자동 확인을 끈 설정은 시험 앱 재시작 후 유지됐으며 수동 확인은 사용할 수 있었습니다.
  하루 전체를 기다려 장시간 반복 주기를 관찰한 것은 아닙니다.
- `tessera.*` 사용자 설정은 전후 의미 값 비교에서 동일했습니다: 2×2+3×2, Gap 0,
  시스템 언어·테마, 기존 방향키와 사용자 최대화 조합 **Option+Command+Return**을 보존했습니다.
  이 비교는 JSON 객체 키 순서와 같은 표현 차이를 제외합니다.
