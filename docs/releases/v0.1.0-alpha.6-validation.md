## 한국어

### 문제 재현

- 5120×2160 울트라와이드 단일 화면(scale 1, 메뉴바 30pt, Gap 0)과 Brave 157.1.99.57에서 재현했다.
  Brave 앱 요소의 `AXEnhancedUserInterface`는 `true`였다.
- 설치된 alpha.5로 Brave 창을 2×2 2열에서 3×2 3열로 넘기면, 크기를 쓴 직후에는 w=1706으로 읽혔다.
  그러나 위치를 쓴 뒤에는 w=2560으로 되돌아가 maxX 5974가 됐다.
- 최근 3일 동안의 Brave 배치 로그 60건은 정상 14건, 화면 안에서 폭이 되돌아간 경우 28건, 화면 밖 18건이었다.
- 같은 전환을 조건마다 세 번 AX로 직접 실행했다.
  - 현재 순서(크기 → 위치): 3회 모두 화면 밖으로 나갔다.
  - 크기를 다시 쓰는 방식: 위치가 되돌아갔다.
  - 쓰는 동안 속성을 끄는 방식: 3회 모두 정확히 배치됐고 1초 뒤에도 유지됐다.

### 실제 Brave 검증

후보와 같은 소스로 프로덕션 `WindowSystem.place` 경로를 실제 Brave 비공개 창에 실행했다.
이 검사는 커밋하지 않은 임시 테스트로 진행했다.

| 경로 | 결과 |
| --- | --- |
| 일시 해제 없음 | `outsideVisibleArea`, x=3414 w=2518, maxX 5932 |
| 일시 해제 | `applied`, x=3414 w=1706, 1초 뒤에도 동일, maxX 5120 |
| 두 경우 모두 | 배치 후 `AXEnhancedUserInterface = true`로 복원 |

새 빌드는 ad hoc 서명이 달라 손쉬운 사용 권한을 다시 받아야 한다. 그래서 후보 앱 자체를 설치해 실행하는 단축키 실측과
alpha.5에서 alpha.6으로의 Sparkle 설치 시험은 이 기록에 포함하지 않는다. 업데이터 코드는 바뀌지 않았다.

## English

### Reproduction

- Reproduced on a single 5120×2160 ultrawide display (scale 1, 30 pt menu bar, Gap 0) with Brave 157.1.99.57,
  whose application element reported `AXEnhancedUserInterface = true`.
- With the installed alpha.5, moving Brave from 2×2 column 2 to 3×2 column 3 read back w=1706 after the size write,
  but the position write reverted it to w=2560, ending at maxX 5974.
- Of 60 Brave placements logged over three days, 14 were correct, 28 reverted width within the display and 18 left it.
- Direct AX runs repeated the move three times per condition.
  - The current size-then-position order overflowed in all three runs.
  - Writing the size again reverted the position instead.
  - Suspending the attribute during the writes placed the window exactly every time, and it stayed there for one second.

### Automated checks and candidate

Swift tests passed: 72 Core + 188 App = 260. The seven new scenarios cover:
- Brave detection.
- Suspension and restore order.
- The issue #11 reproduction and fix.
- Restoration after a failed placement.

The release bundle, nested signatures, updater configuration, runtime paths, 13 public-key verification cases,
49 website tests, JavaScript syntax and diff whitespace checks passed. The existing identity signed the feed and DMG.
The feed lists builds 6, 5 and 4, and `verify-update.swift` plus `SHA256SUMS` confirmed it.
The DMG was mounted read-only to check the app version and build, the Applications link, the bilingual note,
the code signature and the executable hash, then unmounted. Candidate hashes are listed above.

### Native Brave check

From the candidate's source, the production `WindowSystem.place` path ran against a real Brave private window
through an uncommitted, temporary test.
- Without suspension, it ended `outsideVisibleArea` at x=3414 w=2518 (maxX 5932).
- With suspension, it was `applied` at x=3414 w=1706, unchanged after one second.
- `AXEnhancedUserInterface` was restored to `true` in both cases.

The new ad hoc build needs Accessibility permission renewed. This record therefore excludes a shortcut run from the
installed candidate app and a Sparkle installation from alpha.5 to alpha.6. The updater code is unchanged.
