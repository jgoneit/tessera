# alpha.7 배포 검증 / Release validation

로컬 검증 / Local validation: 2026-11-17.
대상 / Target: `0.1.0-alpha.7`, build `7`, macOS arm64.

## 한국어

### 문제 재현

- 5120×2160 단일 화면(scale 1, 메뉴바 30pt, Gap 0)과 Gemini `com.google.GeminiMacOS` 1.144.4.1467에서 재현했다.
  Gemini의 `AXEnhancedUserInterface`는 꺼져 있었다. 창은 `AXStandardWindow`였고 위치·크기는 쓰기 가능으로 보고됐다.
- 설치된 alpha.6에서 Gemini 창을 2×2와 3×2 사이로 넘기면 크기 쓰기가 `-25205`(`attributeUnsupported`)를 반환했다.
  Tessera는 그 자리에서 배치를 멈췄다. 다음 배치의 시작 프레임을 보면 크기는 이미 바뀌어 있었고,
  위치는 옮겨지지 않은 채 "배치 중단" 안내가 떴다.
- AX로 직접 측정한 결과, 크기가 바뀌는 쓰기는 150ms 간격에서 11/11, 1초 간격에서 5/5 모두 `-25205`를 반환했다.
  반환 직후 읽은 크기는 매번 요청한 값이었다. 크기가 바뀌지 않는 쓰기는 오류 없이 끝났다.

### 수정과 리뷰

- `-25205` 응답은 그 쓰기의 readback이 요청 쪽으로 다가갔을 때만 받아들인다.
  요청과 일치하거나, 어느 축에서도 멀어지지 않으면서 한 축 이상 실제로 가까워져야 한다(앱의 크기 제한 허용).
- 아무것도 바뀌지 않은 거부와 시간 초과·다른 AX 오류·권한·대상 변경은 지금처럼 배치를 중단한다.
  쓰기를 추가하거나 반복하지 않는다. 받아들인 응답은 pid와 함께 `acceptedDespiteReply` 단계로 기록한다.
- 독립 리뷰를 두 번 거쳤다.
  - 1차: 첫 구현은 모든 `-25205`를 넘겨 거부된 쓰기까지 성공처럼 보고됐다. readback 증거 판정으로 바꿨다.
  - 2차: 증거 확인용 읽기가 기존 읽기 규칙을 거치지 않았고, 쓰기와 무관하게 창이 변해도 받아들일 수 있었다.
    증거 확인용 읽기를 해당 단계의 readback 자체로 바꿔 실패 시 다시 읽지 않고 같은 프레임을 보고하게 했다.
    판정은 "요청 쪽으로 다가감"으로 좁혔다.
- 모든 AX 오류를 readback으로 판정하자는 제안은 반영하지 않았다.
  응답 시간 초과처럼 응답이 없는 앱에 쓰기를 계속 보내지 않기 위해서다.

### 실제 Gemini 검증

커밋하지 않은 임시 테스트로 실제 Gemini 창을 검사했다. 창은 매번 원래 프레임으로 되돌렸다.
- 1차 리뷰 반영 후, Gemini가 맨 앞일 때 프로덕션 `WindowSystem.place`로 폭이 바뀌는 이동 3회를 실행했다.
  모두 `applied`였고 각 크기 쓰기는 `-25205`를 받아 `acceptedDespiteReply`(pid 16686)로 기록됐다.
- 최종 후보 소스에서는 사용자 작업 앱의 포커스를 빼앗지 않도록 맨 앞 앱 확인을 생략했다.
  대신 `WindowPlacement.perform`에 실제 Gemini AX 읽기·쓰기를 연결해 폭이 바뀌는 이동 4회를 실행했다.
  준비 이동을 포함한 4회 모두 `applied`였고, 0.4초 뒤에도 요청과 같았으며, 매번 `acceptedDespiteReply`를 거쳤다.
- 맨 앞이 아닌 Gemini에 대한 시도는 쓰기 전 검사에서 "활성 창이 바뀜"으로 멈췄고 창은 바뀌지 않았다.

후보 앱 자체를 설치해 단축키로 실측하는 시험과 alpha.6 → alpha.7 Sparkle 설치 시험은 포함하지 않는다.
설치하면 ad hoc 서명이 바뀌어 사용자의 손쉬운 사용 권한 갱신이 필요하다.

## English

### Reproduction

- Reproduced on a single 5120×2160 display (scale 1, 30 pt menu bar, Gap 0) with Gemini
  `com.google.GeminiMacOS` 1.144.4.1467. Gemini's `AXEnhancedUserInterface` was off, its window was
  `AXStandardWindow`, and both position and size reported settable.
- With the installed alpha.6, moving Gemini between 2×2 and 3×2 columns got `-25205` (`attributeUnsupported`) from the size write.
  Tessera stopped there. The next placement's initial frame showed the size had already changed, but the window had not
  moved and a "placement stopped" notice appeared.
- Direct AX runs showed that every size-changing write replied `-25205`: 11 of 11 at 150 ms spacing and 5 of 5 at one second.
  The size read immediately afterwards was always the requested value. Writes that did not change the size succeeded.

### Fix and review

- An attribute-unsupported reply is accepted only when that write's readback moved toward the request. The value must
  match the request, or come closer on at least one axis without moving away on either, which allows an app limit.
- A refused write that changed nothing stays terminal, as do timeouts, other AX replies, permission and target changes.
  No write is added or repeated. Accepted replies are traced with the pid as `acceptedDespiteReply`.
- Two independent review rounds shaped the fix.
  - First round: accepting every `-25205` would make refused writes look successful, so readback evidence replaced it.
  - Second round: the evidence read bypassed the read rules, and unrelated drift could pass as evidence.
    The evidence read is now the stage readback itself, never retried after a failure and reported as the result,
    and the rule was narrowed to progress toward the request.
- The suggestion to judge every AX error by readback was declined, to avoid writing to apps that time out.

### Automated checks and candidate

- Swift tests passed: 72 Core + 197 App = 269, including seven new tests. The Gemini, position, refusal and retry tests fail
  with the check disabled.
- The release bundle, nested signatures, updater configuration, runtime paths, 13 update-verification cases, 49 website tests,
  JavaScript syntax and diff whitespace checks passed.
- The feed lists builds 7, 6, 5 and 4 and verified with `verify-update.swift` and `SHA256SUMS`.
- The DMG was mounted read-only to check the app version and build, Applications link, bilingual note, signature and
  executable hash, then unmounted. Candidate hashes are listed above.

### Native Gemini check

Uncommitted, temporary tests checked a real Gemini window, which was restored after each run.
- After the first review, three width-changing moves through the production `WindowSystem.place` with Gemini frontmost
  were all `applied`. Each size write got `-25205` and was traced as `acceptedDespiteReply` for pid 16686.
- For the final source, the frontmost-app check was skipped so the user's working app kept focus.
  `WindowPlacement.perform` ran with Gemini's real AX reads and writes for four width-changing moves.
  All four were `applied`, one with a preparation move, unchanged after 0.4 s, and each passed `acceptedDespiteReply`.
- Attempts while Gemini was not frontmost stopped at pre-write validation with "the active window changed" and left the window
  unchanged.

This record excludes a shortcut run from the installed candidate app and a Sparkle installation from alpha.6 to alpha.7.
Installing changes the ad hoc signature and requires the user to renew Accessibility permission.
