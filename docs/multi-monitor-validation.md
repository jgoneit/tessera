# 다중 모니터 방향 탐색 검증

검증일: 2026-10-03. 로컬 개발 빌드이며 공개 릴리스는 아니다.

## 원인과 변경

기존 `GridNavigation`은 좌우 경계에서 현재 화면 안으로 순환하고 상하 경계에서는 정지했다.
`AppCoordinator`도 최초 화면에 배치를 고정해 다른 모니터를 목적지로 전달할 수 없었다.

방향별 이웃 화면을 물리적 배치에서 선택하고, 대기 요청에 화면 ID를 함께 저장한다.
실제 쓰기는 목적지의 작업 영역·배율로 계산하며 화면 구성이 바뀐 요청은 거부한다.
선택기는 같은 패널을 유지한 채 목적지로 옮겨 키 입력과 화면 표시를 이어간다.

첫 구현은 이웃 화면이 없는 바깥 경계에서 여전히 현재 화면 안으로 순환했다.
좌우로 연결된 화면의 바깥 경계를 반대편 끝 모니터에 연결하도록 보완했다.
왼쪽 끝에서 왼쪽을 누르면 맨 오른쪽 화면 마지막 열로, 오른쪽 끝에서 오른쪽을 누르면
맨 왼쪽 화면 첫 열로 이동한다. 단일 화면의 순환과 상하 끝의 정지는 유지한다.

## 실제 환경

- 내장 Retina: AppKit frame `(0, 0, 1512, 982)`, visible frame `(0, 0, 1512, 949)`, scale 2.
- 왼쪽 TFG40U12PW: 첫 시험 frame `(-5120, -1178, 5120, 2160)`, 바깥 경계 보완 빌드 설치 후 frame `(-5120, -716, 5120, 2160)`, scale 1. 사용 중 화면 배치가 바뀌었으므로 각 요청 시점의 작업 영역으로 검증한다.
- 기존 격자 2×2+3×2, Gap 0, Control+Option+방향키/Return 설정을 사용한다.
- 최종 시험 실행 파일 SHA-256: `ebb8001243fc0fd08fd94b081ed18d91189c3b6e4c43b11fb5032561b63f6128`.
- 첫 시험에서 Brave 전역 단축키의 내장↔외장 이동과 목적지 좌표의 AX 최종 읽기를 확인했다. 내장 화면의 3×2 열 너비 504pt 요청은 Brave의 최소 너비 594pt로 제한되어 안내됐다.
- 첫 외장 진입에서 요청 높이 2130pt가 952pt로 제한되고 다음 배치는 2130pt를 수용하는 현상을 실제 로그에서 발견했다. 화면 전환 시에만 최종 이동 후 크기를 한 번 재적용하도록 보완했다. 일반 단일 화면 배치는 기존 쓰기 횟수를 유지한다.
- 바깥 경계 순환을 추가한 최신 빌드는 설치·서명 확인 후 PID 42242로 재실행했으며, macOS 인증 후 기존 손쉬운 사용 권한을 갱신하고 앱의 준비 상태를 확인했다.
- 사용자가 직접 전역 단축키를 입력한 뒤 최신 실행 프로세스의 로그를 읽었다. 09:27:30–09:27:49 구간의 ChatGPT 창 배치 43건 모두 요청 프레임과 최종 AX 프레임이 일치했다. 이 중 모니터 사이 이동은 10건이며 바깥 경계 순환은 좌우 각각 3건이다.
- 왼쪽 외장 첫 열에서 왼쪽 입력: `(-5120, -432, 1707, 2130)` → 오른쪽 내장 마지막 열 `(1008, 33, 504, 949)`을 확인했다. 반대 바깥 경계의 오른쪽 입력도 두 프레임의 역방향으로 적용됐다. 좌표는 AX의 `(x, y, width, height)`이다.
- 최신 빌드에서 ChatGPT는 외장 진입 첫 요청부터 높이 2130pt를 수용했다. 앞서 Brave에서 발견한 크기 재시도 경로는 자동 검사만 완료했으며, Brave에서의 재검증과 실제 숫자 선택기 패널 이동은 남아 있다. 자동 입력은 전역 단축키를 전달하지 못했고, 선택기 확인을 위해 설정 창을 닫는 과정에서는 도구 연결 오류(`native pipe closed before response`)가 발생했다. 선택기 목적지·숫자·최대화의 상태 검증은 자동 검사에 포함됐다.
- 물리적 상하 배치·3대 연결·연결 해제 조합은 자동 검사 범위이며 실제 장치 검증과 구분한다.
- 격자·간격·언어·테마·다섯 단축키의 설치 전후 저장값이 동일했다. 바깥 경계 보완 설치 전후에도 전체 환경설정의 변경 키는 없었다. 단축키 JSON은 직렬화 순서와 무관하게 객체 내용으로 비교했다.
