# 다중 모니터 방향키 분할 배치

Status: Ready

## 목표

선택한 격자를 방향키로 탐색하다 화면 끝에 도달하면, 같은 방향에 있는 다른 모니터의 격자로 이어서 현재 창을 배치할 수 있다. 좌우로 이어진 화면의 가장 바깥 경계는 전체 화면의 반대쪽 끝으로 순환한다. 직접 단축키와 메뉴의 창 배치 선택기가 같은 규칙을 사용한다.

## 범위

- 좌우·상하 모니터 연결, 목적지 화면의 작업 영역과 배율, 선택기 표시 위치, 연속 입력의 목적지 유지.
- 기존 단일 화면 탐색, 최대화, 앱 크기 제한 안내, 창 확보와 취소 동작 유지.
- 사용자가 연결한 듀얼 모니터에서 로컬 시험 빌드로 실제 이동을 검증한다.
- 새 단축키·설정, 여러 화면에 걸친 하나의 창 분할, macOS Space 이동, 공개 배포는 범위에 포함하지 않는다.

## 제약과 설계 판단

- macOS의 화면 배치를 기준으로 방향을 정한다. 입력 방향으로 현재 화면 경계를 지난 화면 중 수직 방향 투영 구간이 겹치는 화면을 우선하고, 경계 거리·수직 방향 중심 거리·화면 ID 순으로 결정한다. 대각선 배치는 겹치는 후보가 없을 때 사용하며, 미러링으로 겹친 화면은 이웃으로 취급하지 않는다.
- 좌우는 모든 활성 격자의 열 중심 순서를 유지한다. 끝에서 이웃 화면의 반대쪽 끝 열로 진입하며 위/전체/아래 높이를 보존한다.
- 위쪽 반칸에서 다시 위를 누르면 위 모니터의 아래 반칸, 아래 반칸에서 다시 아래를 누르면 아래 모니터의 위 반칸으로 이동한다. 격자와 열, 화면 전체 너비 여부를 보존한다. 위아래 길게 누르기는 여전히 한 번만 반영한다.
- 좌우 방향에 이웃이 없으면 반대 방향의 가장 바깥 화면으로 순환한다. 왼쪽 끝에서 왼쪽 입력은 맨 오른쪽 화면의 마지막 열, 오른쪽 끝에서 오른쪽 입력은 맨 왼쪽 화면의 첫 열로 이동한다. 바깥 경계가 같은 후보는 높이 겹침·세로 중심 거리·화면 ID 순으로 결정한다.
- 좌우로 떨어진 다른 화면이 없으면 현재 화면 안에서 순환한다. 위아래는 해당 방향의 이웃이 없으면 멈춘다. 별도 화면 이동 키를 추가하는 대신 기존 방향 흐름을 확장한다.
- 배치 요청은 생성 당시 화면과 격자를 보존한다. 앱의 최소 크기 때문에 실제 프레임이 달라져도 수동 변경 전까지 논리적인 탐색 위치를 유지한다.

## Acceptance Criteria

- **AC-1** 직접 방향 단축키와 메뉴 선택기에서 화면 끝을 넘어 입력하면 같은 창이 해당 방향의 다른 모니터 격자에 배치된다. 좌우, 상하, 3대 이상 연결에서 다음 이동을 이어갈 수 있다.
- **AC-2** 이동 후 창의 분할 크기·위치는 목적지의 메뉴바·Dock 제외 작업 영역, 간격, 배율을 따른다. 음수 좌표와 서로 다른 해상도에서도 적용되며 앱 크기 제한은 기존 방식으로 안내된다.
- **AC-3** 화면 전환 후 선택기 위치·화면 이름·격자 미리보기가 목적지를 나타낸다. 숫자·클릭·최대화는 표시된 모니터에 적용되고, 선택기 키 입력을 계속 받을 수 있다.
- **AC-4** 빠른 연속 입력에서 배치는 직렬 실행되고 최신 대기 목적지를 적용한다. 앞선 요청의 완료가 이후 선택 화면을 되돌리지 않는다. 모니터 연결·배치·작업 영역·배율이 바뀌면 이전 요청으로 다른 화면을 잘못 배치하지 않는다.
- **AC-5** 좌우로 떨어진 다른 화면이 없으면 현재 화면의 좌우 순환을 유지하고, 위아래 이웃이 없으면 정지한다. 활성 격자 순서, 최대화에서 격자 진입, 위아래 반복 억제, 사용자 단축키·설정 유지가 보존된다. 대상 창·활성 앱 변경과 취소 후 새 쓰기가 이어지지 않는다.
- **AC-6** 듀얼 모니터의 왼쪽 화면 첫 열에서 왼쪽을 누르면 오른쪽 화면 마지막 열로, 오른쪽 화면 마지막 열에서 오른쪽을 누르면 왼쪽 화면 첫 열로 이동한다. 3대 이상에서도 양 끝을 연결해 전체 화면을 순환하며, 활성 격자 순서와 위/전체/아래 높이를 보존한다.

## 사용 시나리오

| 종류 | 시나리오 | 조건 |
| --- | --- | --- |
| 흐름 | 왼쪽 모니터 마지막 열에서 오른쪽을 누르고 오른쪽 모니터 첫 열로 옮긴 뒤 다음 열을 선택한다. 반대 방향도 이어진다. | AC-1, AC-2 |
| 흐름 | 왼쪽 화면 첫 열에서 왼쪽을 눌러 오른쪽 화면 마지막 열로 이동하고, 오른쪽을 눌러 원래 위치로 돌아온다. 3대 연결에서도 양 끝 사이를 이동한다. | AC-2, AC-6 |
| 흐름 | 위아래로 연결한 화면에서 반칸을 넘어 이동한 뒤 전체 열·최대화를 적용한다. | AC-1, AC-2, AC-5 |
| 흐름 | 메뉴 선택기에서 다른 화면으로 이동하고 이동한 선택기의 숫자나 버튼으로 영역을 확정한다. | AC-3 |
| 경계 | 쓰기가 끝나기 전에 여러 화면으로 이동해도 마지막 목적지가 적용된다. 도중에 모니터가 빠지거나 배치가 바뀌면 이전 요청은 중단된다. | AC-4 |
| 경계 | 큰 최소 크기를 가진 창을 작은 화면에 배치하면 실제 적용 결과를 안내하고 다음 방향 입력의 논리 상태는 유지한다. | AC-2, AC-4 |
| 유지 | 단일 화면의 좌우 순환과 이웃 없는 위아래 방향의 정지를 유지하고, 앱 전환이나 외부 클릭으로 대기 배치를 취소한다. | AC-5 |

## 관련 맥락

- `Sources/TesseraCore/GridNavigation.swift`: 격자 순서와 화면 경계 단계.
- `Sources/TesseraCore/DisplayGeometry.swift`: 화면 좌표, 방향별 이웃 선택과 좌우 바깥 경계 순환.
- `Sources/TesseraApp/DirectNavigationState.swift`, `ScreenCatalog.swift`: 논리 목적지, 실제 창 프레임, 화면 구성.
- `Sources/TesseraApp/AppCoordinator.swift`, `OverlayController.swift`, `PlacementQueue.swift`: 입력부터 선택기와 실제 창 배치까지의 연결.
