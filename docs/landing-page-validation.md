## 실제 브라우저 검증

Codex 내장 브라우저에서 로컬 HTTP 서버로 페이지를 열어 확인했다.

- 1280×900 데스크톱 다크/라이트와 390×844, 320×740 라이트 화면을 확인했다.
  좁은 화면에서 문서의 scrollWidth가 viewport width와 같아 가로 넘침이 없었다.
- 3×2 초기 상태에서 2·5번을 하나의 연결된 테두리로 강조하고,
  예시 창이 가운데 열 전체를 채우는 것을 확인했다.
- 클릭 순서 `↑ ↓ ↓ ↓ ↑`의 결과가 위칸 → 전체 → 아래칸 → 아래칸 → 전체였다.
- 2×2를 함께 선택한 뒤 가운데 3분할에서 오른쪽으로 이동하면
  `2×2 · 2열 전체`가 되고 번호가 1–4로 바뀌었다.
- 4×2만 선택하면 1–4가 위 행, 5–8이 아래 행에 놓인다.
  마지막 격자의 체크박스는 비활성화돼 빈 선택을 막았다.
- 방향 버튼 클릭 후 키보드 ↑ 입력이 다음 높이로 한 단계 이동했다.
- 숫자 `2`, `↓`, `↓` 입력은 위칸 → 전체 → 아래칸으로 이동했다.
- Control을 누른 방향키는 웹 데모에서 처리하지 않아 선택을 유지했다.
- Esc와 체험 영역 밖 클릭 후 포커스가 체험 영역 밖에 있는 것을 확인했다.
- 확인 시점의 브라우저 error 로그는 비어 있었다.

## Seal과 검증 한계

Basic Task `tessera-landing-demo-20260919`는 기존 카탈로그의 `unit-tests`,
`app-bundle`(각 300초)을 사용한다. 이 검사는 기존 Swift 앱의 회귀/번들 검증이며
위의 웹 모델 테스트와 브라우저 검증을 대신하지 않는다. 정확한 Run과 Completion
결과는 해당 Seal Task에 기록한다.

웹 데모는 실제 창 이동 없이 예시 창 하나를 움직인다. 숫자나 클릭 후에는 반복 체험을
위해 선택기를 유지하며, 실제 앱의 선택기 닫힘 동작을 재현하지 않는다.
AX 권한·실제 앱 최소 크기·네이티브 키 반복·한글 입력·다중 화면의 검증은 이번
웹 시안 작업에 포함하지 않는다. 기존 다중 화면 미완료 항목도 그대로 남는다.
Safari/Chrome 별도 브라우저와 VoiceOver 직접 조작은 수행하지 않았다.

## GitHub Pages 배포 준비

- 승인된 시안과 네이티브 앱을 그대로 유지하고 자동 배포 워크플로를 추가했다.
- 필요한 정적 파일 다섯 개만 배포 디렉터리에 복사하며 테스트·README·앱 저장소는
  배포 대상에서 제외한다.
- `/tessera/` 하위 경로에 필요한 파일과 module import가 모두 상대 경로임을 확인했다.
- 외부 다운로드·설치 안내·저장소 링크는 익명 HTTP 요청에서 200 응답을 확인했다.
- 배포 전에 웹 테스트 16개와 JavaScript 구문 검사를 다시 통과했다.
- 새 Basic Task `tessera-github-pages-20260919`는 기존 필수 앱 검사 두 개를 유지한다.
  웹 동작은 별도 Node 검사와 브라우저 검증으로 구분한다.
- 실제 배포 결과는 GitHub Actions의 `Publish Tessera website` 실행에 기록하며,
  게시 후 공개 URL과 모듈 응답, 데모 조작을 별도로 확인한다.
