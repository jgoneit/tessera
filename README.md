# Tessera

[한국어](README.md) | [English](README.en.md)

[소개 페이지](https://jgoneit.github.io/tessera/?lang=ko)

macOS용 **Grid-first Window Manager**. 현재 창을 격자의 열이나 번호가 있는 Zone에 배치합니다.
SwiftUI·AppKit·Accessibility API로 만든 메뉴바 앱이며 외부 패키지를 사용하지 않습니다.

## 빌드와 실행

macOS 14 이상, Swift 6 이상과 macOS SDK가 필요합니다. 현재 Mac의 아키텍처로 빌드합니다.

```sh
swift test
bash scripts/build-app.sh
open dist/Tessera.app
```

## 응용 프로그램 설치와 DMG

일상적으로 사용할 때는 빌드한 `Tessera.app`을 `/Applications`(응용 프로그램)에 복사하고
그 위치에서 실행합니다. 같은 Mac에 설치하는 데 웹 공개나 Apple Developer Program 가입은 필요하지 않습니다.
개발용 `dist` 경로의 앱과 설치한 앱을 동시에 실행하지 마세요. 앱은 메뉴바에 상주하며 Dock 아이콘은 표시하지 않습니다.

```sh
bash scripts/build-dmg.sh
```

`dist`에 버전·아키텍처가 표시된 DMG를 생성합니다. DMG 안의 Tessera를 Applications로 드래그해 설치합니다.
이미 검증한 앱을 다시 빌드하지 않고 포장하려면 `bash scripts/build-dmg.sh --skip-build`를 사용합니다.
설치·업데이트·손쉬운 사용 권한 안내는 [설치 안내](docs/INSTALL.md)를 참고하세요.

현재 앱은 로컬 ad hoc 서명이며 Apple 공증을 받지 않았습니다. DMG는 설치용 포장으로,
Developer ID 서명·공증을 대신하지 않습니다. 인터넷에서 내려받은 앱은 macOS의 확인 경고로 실행이 차단될 수 있습니다.
일반 사용자 대상 배포에서 Developer ID 서명과 공증을 사용하려면 Apple Developer Program이 필요합니다.
[Apple Developer ID 안내](https://developer.apple.com/developer-id/)와
[Apple의 앱 실행 안내](https://support.apple.com/102445)를 참고하세요.

현재 스크립트는 빌드한 Mac의 아키텍처용 DMG를 만듭니다. Apple Silicon의 `arm64` 빌드를
Intel Mac용 또는 universal 앱으로 표시하지 않습니다. DMG 생성은 웹 업로드나 공개 릴리스를 수행하지 않습니다.

## 앱 번들

빌드 스크립트는 release 실행 파일·Info.plist·앱 아이콘을 `dist/Tessera.app`에 묶고,
로컬 ad hoc 서명과 번들 검증을 수행합니다. Xcode 프로젝트 생성이나 별도 패키지 설치는 필요하지 않습니다.
앱은 Dock 대신 메뉴바의 단색 세 칸 아이콘 하나로 상주합니다. 앱 이름은 표시하지 않으며,
template 이미지가 메뉴바 배경과 선택 상태에 맞춰 표시됩니다. 툴팁과 접근성 이름은 유지합니다.
앱·설정 화면은 제공된 컬러 원본 이미지를 사용하며, 빌드 시 표준 macOS 아이콘 크기를 생성합니다.
앱을 다시 열면 Settings가 표시되며, 화면 아래에서 마지막 작업 결과를 확인할 수 있습니다.

일부 Command Line Tools 배포본의 Swift Testing 매크로 탐색 누락은 manifest가
활성 컴파일러의 번들 디렉터리를 찾아 보완합니다. 사용자·SDK의 절대 경로를 고정하지 않습니다.

## 사용 방법

1. 첫 실행의 설정 화면에서 **설정 열기 / Open Settings**를 선택합니다.
2. **시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용**에서 Tessera를 허용합니다.
   목록에 없다면 `+`로 설치한 `/Applications/Tessera.app`을 추가합니다. 개발용 실행은 실제 `dist/Tessera.app` 경로를 사용합니다.
3. Tessera 설정으로 돌아와 새로고침 아이콘(**다시 확인 / Check Again**)으로 권한을 확인합니다.
4. **격자 / Layouts**에서 2×2·3×2·4×2 중 사용할 격자를 하나 이상 선택합니다. 처음에는 3×2만 선택됩니다.
5. 다른 앱의 일반 창을 활성화하고 다음 방향 단축키를 누릅니다.

| 기본 단축키 | 동작 |
| --- | --- |
| Control+Option+← | 현재 높이를 유지하며 선택한 격자들의 왼쪽 후보 열로 이동 |
| Control+Option+→ | 현재 높이를 유지하며 선택한 격자들의 오른쪽 후보 열로 이동 |
| Control+Option+↑ | 아래쪽 한 칸 → 열 전체 → 위쪽 한 칸 |
| Control+Option+↓ | 위쪽 한 칸 → 열 전체 → 아래쪽 한 칸 |

전역 단축키는 선택기를 열지 않고 창을 바로 배치합니다. 원래 앱의 키보드 포커스를 유지하며,
성공 안내는 약 1초, 오류나 앱 제약 안내는 약 4초 표시합니다. 일반 방향키는 원래 앱에서 계속 사용할 수 있습니다.

좌우는 선택한 모든 격자의 열 중심을 화면 왼쪽에서 오른쪽 순서로 탐색하고, 양 끝에서 순환합니다.
예를 들어 2×2와 3×2를 함께 선택하면 `3×2의 1열 → 2×2의 1열 → 3×2의 2열 → 2×2의 2열 → 3×2의 3열` 순서입니다.
이동 중 격자가 바뀌면 창 너비도 해당 격자에 맞게 바뀌며 위·전체·아래 높이 단계는 유지합니다.
상하는 현재 격자와 열을 유지합니다. 길게 누르면 좌우만 Tessera가 반복 이동을 처리하며,
키나 필요한 보조키를 놓으면 반복을 멈춥니다. 상하는 한 번 누를 때 한 단계만 이동하므로
다음 단계로 가려면 키를 놓고 다시 누릅니다. 위·아래 끝에서는 더 이동하지 않습니다.
3×2만 선택한 경우 가운데 열 `(2·5)`에서 `⌃⌥↑ → ⌃⌥→ → ⌃⌥→ → ⌃⌥↓`는
`2 → 3 → 1 → (1·4)`로 배치합니다. 열 전체는 두 Zone 사이의 Gap까지 하나의 창으로 채우고 바깥 Gap은 유지합니다.

## 메뉴의 Zone 선택기

메뉴바의 **Arrange Window…**는 번호와 격자가 보이는 선택기를 엽니다.
열기만 해서는 창을 움직이지 않습니다. 메뉴를 열기 전에 확보한 같은 창을 끝까지 사용합니다.

- 일반 방향키 또는 등록된 방향 단축키로 즉시 배치하며, 선택기를 계속 열어 둡니다.
- 현재 선택된 열의 격자와 Zone 번호를 표시합니다. 좌우 이동으로 격자가 바뀌면 표시되는 격자도 바뀝니다.
- Zone 클릭이나 숫자키·숫자패드 **1–4 / 1–6 / 1–8**은 현재 표시된 2×2 / 3×2 / 4×2의 한 칸에 배치하고 닫습니다.
  표시된 격자의 범위를 벗어난 숫자는 창을 움직이지 않습니다.
- **Enter / Esc**는 선택기를 닫고 이미 받은 마지막 배치 요청까지 완료합니다. 적용된 위치·크기는 유지합니다.
- 바깥 클릭·다른 앱 활성화·화면 구성 변경은 대기 요청을 버리고 다음 쓰기 전에 중단합니다.
  이미 적용한 변경은 복원하지 않습니다.

## 설정

| 설정 | 선택지 | 기본값 |
| --- | --- | --- |
| 격자 / Layouts | 2×2, 3×2, 4×2 중 하나 이상 | 3×2만 선택 |
| 창 간격 / Window spacing | 0, 4, 8, 12pt | 8pt |
| Left / Right / Up / Down | 방향마다 서로 다른 키 조합 | Control+Option+각 방향키 |

Zone 번호는 좌상단에서 시작해 왼쪽에서 오른쪽, 위에서 아래 순서입니다.
Gap은 인접 창 사이와 화면 가장자리에 똑같이 적용합니다.
메뉴바와 설정의 레이아웃은 같은 값을 공유하며 모든 설정은 앱 재시작 후에도 유지됩니다.
마지막으로 남은 격자는 해제할 수 없습니다. 격자 선택이나 Gap을 바꾸면 진행 중인 입력·배치를 취소하고,
다음 단축키에서 현재 창을 다시 확인합니다.

설정의 **방향 단축키 / Direction shortcuts**를 펼치고 각 버튼을 눌러 조합을 녹화한 뒤
**단축키 적용 / Apply Shortcuts**으로 네 개를 함께 적용합니다. 정상 등록 상태에서는 이 항목을 접어 둡니다.
조합에는 Command·Control·Option 중 하나 이상이 필요하며, 네 방향에 같은 조합을 중복 지정할 수 없습니다.
Esc는 녹화를 취소합니다. 두 방향의 키를 맞바꾸려면 두 draft를 모두 수정한 후 적용하면 됩니다.
녹화 중에도 기존 네 단축키의 등록은 유지되며, 등록된 키를 눌러도 창을 이동하지 않고 활성 draft만 변경합니다.

새 묶음의 등록에 실패하면 기존 단축키와 저장값을 유지하고 충돌 이유를 표시합니다.
시작할 때 네 개를 모두 등록하지 못하면 Settings에 비활성 상태와 오류가 표시됩니다.
표시 이름은 ANSI 키보드 기준이고 입력은 물리적 키 코드로 처리하므로 한글 입력 상태에서도 같은 키를 사용합니다.

이전 버전의 단일 전역키 설정은 새 네 방향 기본값으로 전환합니다. 기존 Layout·Gap은 유지합니다.
네 방향 설정은 v2 저장 키로 관리하며, 손상되거나 일부 방향이 빠진 값·중복 조합은 묶음 전체를 기본값으로 복구합니다.
이전 **Control+Option+Space** 선택기 호출은 메뉴의 **Arrange Window…**로 대체됩니다.
기존 단일 Layout 설정은 같은 격자 하나가 선택된 상태로 이전합니다. 새 선택 목록은 2×2·3×2·4×2 순서로
저장하며 중복은 제거합니다. 새 목록이 비어 있거나 형식·격자 이름이 잘못되면 3×2만 선택한 상태로 복구합니다.

## 언어와 테마

설정의 **화면 표시 / Appearance**에서 언어와 테마를 변경합니다. 앱을 다시 열지 않아도 반영되며,
설정·메뉴·선택기·결과와 오류 안내에 적용됩니다.

- 언어: 시스템, 한국어, English. 시스템은 macOS 선호 언어 중 지원하는 첫 언어를 사용하며 영어로 대체할 수 있습니다.
- 테마: 시스템, 라이트, 다크. 시스템은 macOS의 자동 밝기 모드 전환도 따릅니다.
- 새 설치는 언어와 테마 모두 시스템입니다. `tessera.language.v1` / `tessera.theme.v1`에 저장하고,
  손상되거나 지원하지 않는 값은 시스템으로 복구합니다. 기존 격자·간격·단축키 설정은 유지합니다.
- 화면은 macOS 의미 색상을 사용합니다. 선택기는 투명도 줄이기·대비 증가 설정을 반영하며,
  선택 테두리와 체크 표시를 함께 사용합니다. 창 배치 방식과 단축키는 바뀌지 않습니다.
- 권한 허용 후에는 작은 상태 행으로 표시하고, 격자 설정에 더 많은 공간을 둡니다.
  선택기의 키 안내는 폭에 따라 한 줄 또는 두 줄로 배치되며 현재 격자의 숫자 범위와 종료 동작을 표시합니다.

한국어·영어 번역 리소스는 앱 번들 안에 포함됩니다. 빌드 스크립트가 두 리소스를 검사하고 함께 서명합니다.
UI 렌더 검증용 이미지는 선택적으로 다음 명령으로 만들 수 있습니다. 화면을 활성화하거나 실제 창을 이동하지 않습니다.

```sh
TESSERA_UI_PREVIEW_DIR="$PWD/.build/ui-previews" swift test
```

## 창과 화면 처리

- 창과 가장 많이 겹치는 화면의 `NSScreen.visibleFrame`을 사용해 Dock·메뉴바 영역을 제외합니다.
- 모든 좌표는 논리적 point입니다. pixel 정렬에는 해당 화면의 backing scale을 사용합니다.
- AX의 좌상단 좌표와 AppKit의 좌하단 좌표는 항상 기준 화면의 상단을 통해 변환합니다.
- 현재 창이 선택한 격자 중 한 열의 위·전체·아래 프레임과 일치하면 그 단계에서 시작합니다.
  일치하지 않으면 선택기는 창 중심에 가장 가까운 후보의 열 전체를 강조하고, 거리 동률이면 왼쪽을 택합니다.
  이 상태에서 첫 좌우 입력은 강조된 후보를 기준으로 한 칸 건너뛰지 않고, 원래 창 중심의 해당 방향에 있는
  가장 가까운 후보로 이동합니다. 첫 상하 입력은 강조된 열 전체에서 위·아래 단계로 이동합니다.
- 같은 창에 연속 입력할 때는 방향 이동 단계를 유지하고 AX에서 확인한 실제 프레임을 별도로 기록합니다.
  앱의 크기 제한으로 요청과 실제 프레임이 달라도 상하 단계가 다시 초기화되지 않습니다.
- 다른 창·화면·선택한 격자 목록·Gap으로 바뀌거나 사용자가 창을 직접 옮기고 크기를 바꾸면 다음 입력에서
  현재 창과 프레임을 다시 확인합니다. 대상 창이 사라지거나 유효하지 않으면 배치를 중단합니다.
- AX 준비 중 들어온 방향 입력은 순서대로 반영합니다. 실제 크기·위치 쓰기는 직렬 실행하며,
  실행 중인 배치 다음에는 마지막 대기 위치를 적용하므로 중간 위치가 모두 화면에 표시되지는 않을 수 있습니다.
- 현재 위치에서 요청한 크기로 바꾸면 화면을 벗어나는 경우, 크기를 바꿀 공간을 확보하도록 먼저 한 번 이동합니다.
  현재 크기와 요청 크기 중 큰 너비·높이를 기준으로 현재 원점을 화면 안으로 보정합니다.
  이어서 크기 요청 → 실제 크기 확인 → 최종 위치 보정 → 최종 프레임 확인을 수행합니다.
  위치·크기 쓰기는 최대 세 번이며, 매 쓰기 전 대상과 취소 상태 등을 다시 확인하고 재시도하지 않습니다.
- 앱의 최소 크기·크기 단위 제한 때문에 정확히 배치되지 않으면 제약을 안내합니다.
  창의 최소 크기가 화면보다 크면 화면 안에 완전히 들어간다고 표시하지 않습니다.
- AX 위치·크기 변경은 원자적이지 않습니다. 사전 이동을 포함해 쓰기를 한 번이라도 시도한 뒤 실패하면
  부분 변경 가능성을 알립니다. 자동 복원은 하지 않습니다.
- Desktop, 특수 창, 모달, 최소화 상태, 이동·크기 변경 불가 창은 대상에서 제외합니다.
- 네이티브 전체 화면은 지원하지 않습니다. 앱이 제공하는 전체 화면 속성으로 감지 가능한 경우 거절하며,
  전체 화면 해제나 Spaces 전환은 하지 않습니다. 모든 앱의 전체 화면 상태를 감지할 수 있다는 보장은 없습니다.

접근성 권한이 없어도 앱과 설정은 동작합니다. 권한을 철회하면 배치 요청을 중단합니다.
ad hoc 서명은 배포용 Developer ID 서명과 다릅니다. 재빌드 후 권한이 풀리거나 앱이 중복 표시되면
시스템 설정에서 기존 Tessera 항목을 제거하고 **현재 빌드 경로**의 앱을 다시 허용해야 할 수 있습니다.
시스템 설정에는 켜짐으로 표시되더라도 앱에 `Accessibility access is required`가 남아 있으면
기존 항목 제거 → 현재 앱 다시 추가 → 앱 재시작 → **Check Again** 순서로 확인합니다.

단축키에 반응하지 않는 경우 로컬 진단 로그에서 등록·이벤트 수신·배치 결과를 구분할 수 있습니다.
배치 로그에는 대상 PID와 요청·초기·사전 이동·크기 변경 후·최종 프레임을 기록합니다.
입력한 문서 내용과 창 제목은 기록하지 않으며 외부 전송은 하지 않습니다.

```sh
/usr/bin/log show --last 5m --style compact --info \
  --predicate 'subsystem == "io.github.jgoneit.tessera"'
```

## 구조와 검증

- `TesseraCore`: 프리셋·정규화 Zone·Geometry·방향 탐색·좌표 변환·화면 선택. AppKit·AX에 의존하지 않습니다.
- `TesseraApp`: 메뉴바·선택기·전역 단축키 등록과 반복 처리·설정·연속 배치 상태와 actor 내부 AX 제어.
- `Tests`: Geometry·화면 선택·좌표 변환·방향 이동·설정 복구와 이전·녹화·단축키 등록 실패·배치 대기열·번들 메타데이터.

```sh
swift test
bash scripts/build-app.sh
```

두 명령은 Seal 필수 검사에도 등록되어 있습니다. 빌드·테스트 통과와 실제 창 이동 검증은 별도 증거입니다.
실기 검증 절차와 현재 결과는 [검증 기록](docs/validation.md)에 기록합니다.

v0.1에는 드래그 Snap, 임의 Zone 병합, 사용자 레이아웃 편집, 앱별 규칙, Workspace 복원,
계정·네트워크·텔레메트리·AI 기능을 포함하지 않습니다. 열 전체 배치는 정해진 한 열만 대상으로 합니다.
